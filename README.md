# KEEP THE PACE — F45 연신내 출석 이벤트

F45 연신내 스튜디오의 추석 연휴 이후 출석 활성화 이벤트를 위한 **완전 독립형** 웹앱입니다.
기존 CRM, 회원관리 시스템과 전혀 연동하지 않으며, 이 이벤트 운영에만 필요한 최소한의 기능으로 구성되어 있습니다.

- 멤버는 스튜디오 QR을 스캔 → 본인 확인(또는 최초 등록) → 오늘의 출석 코드 입력 → 5초 안에 출석 완료
- 주 3회(설정 가능) 이상 출석하면 자동으로 "이번 주 성공" 처리
- 관리자는 매 수업 명단을 확인할 필요 없이 **"이번 주 성공자 리스트"** 만 보면 됩니다

## 기술 스택

- Next.js 16 (App Router) + TypeScript
- Tailwind CSS v4
- Supabase (Postgres + Auth) — 서버 라우트에서만 접근, 브라우저는 DB에 직접 접근하지 않음
- Vercel 배포 대상

## 1. 로컬 개발 환경 설정

```bash
npm install
cp .env.example .env.local   # 값 채워넣기 (아래 2번 참고)
npm run dev
```

## 2. Supabase 프로젝트 설정

1. [supabase.com](https://supabase.com) 에서 새 프로젝트를 생성합니다. (기존 CRM용 프로젝트와 **별도**로 새로 만드세요)
2. `Project Settings → API` 에서 다음 값을 확인해 `.env.local` 에 채워넣습니다.
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (anon public key)
   - `SUPABASE_SERVICE_ROLE_KEY` (service_role key — 절대 외부 노출 금지)
3. `DAILY_CODE_SECRET` 은 아무 값이나 충분히 긴 랜덤 문자열로 설정합니다. (`openssl rand -hex 32` 추천)
4. Supabase 대시보드의 **SQL Editor** 에서 `supabase/schema.sql` 파일 내용을 그대로 실행합니다.
   - `members`, `checkins`, `events` 테이블이 생성되고, `events`에 기본 이벤트 1건이 생성됩니다.
   - `(member_id, checkin_date)` 에 unique 제약이 걸려 있어 **같은 날 중복 출석이 DB 레벨에서 원천 차단**됩니다.
5. **관리자 계정 생성**: `Authentication → Users → Add user` 에서 스태프 이메일/비밀번호로 계정을 만듭니다.
   - 이 프로젝트는 별도 회원가입 화면이 없습니다. 관리자는 Supabase에서 수동으로만 생성됩니다.
   - `/admin` 은 로그인된 Supabase Auth 사용자라면 누구나 접근 가능한 구조이므로, 스태프 계정만 생성하세요.

## 3. Vercel 배포

1. 이 리포지토리를 GitHub 등에 올리고 Vercel에서 Import 합니다.
2. Vercel 프로젝트의 Environment Variables에 `.env.local`과 동일한 4개 값을 등록합니다.
3. Deploy. 빌드/런타임에 별도 설정이 필요 없습니다 (Node.js 런타임 기본 사용).
4. 배포된 주소(예: `https://keep-the-pace.vercel.app`)로 **고정 QR코드 1개**를 만들어 스튜디오에 비치하면 끝입니다. 이벤트 기간 내내 QR을 새로 만들 필요가 없습니다.

## 4. 부정 사용(어뷰징) 방지 — 매일 바뀌는 4자리 코드

QR 자체는 고정 주소이기 때문에, 집에서 URL을 저장해두고 실제로 스튜디오에 오지 않은 날 체크인하는 것을 막기 위해
**날짜 기준으로 서버가 자동 생성하는 4자리 코드**를 도입했습니다.

- 코드는 `오늘 날짜 + DAILY_CODE_SECRET` 을 HMAC-SHA256으로 해싱해 결정론적으로 생성됩니다.
  → 스태프가 매일 코드를 만들거나 입력할 필요가 전혀 없습니다. 자정이 지나면 자동으로 새 코드로 바뀝니다.
- 스태프는 `/admin` 대시보드(또는 전체화면용 `/admin/today-code`)에 표시되는 오늘의 코드를 스튜디오 TV나 데스크 모니터에 띄워두기만 하면 됩니다.
- 멤버는 QR 스캔 → 본인 확인 → **스튜디오에 표시된 코드 입력** → 출석 완료 순서로 진행되며, 코드를 모르면 체크인이 불가능합니다.
- GPS 등 복잡하거나 멤버에게 불편한 방식 대신, 운영이 가장 쉬운 "매일 바뀌는 공개 코드" 방식을 채택했습니다. 완벽한 부정 방지는 아니지만(같은 날 스튜디오에 있던 누군가에게 코드를 전해 듣고 집에서 체크인하는 극단적 케이스는 막지 못함), 100% 자동화된 상태에서 현실적으로 가장 운영 부담이 적은 1차 방어선입니다.
- 추가로 막고 싶다면(선택 사항): 코드를 매일 오전 특정 시간에만 노출하거나, Wi-Fi 캡티브 포털 안내 문구에 코드를 함께 노출하는 방식도 고려할 수 있습니다.

## 5. 데이터 모델

```
events    (이벤트 기간 · 주당 목표 출석 횟수 — 운영 중 1행만 사용)
members   (이름 · 전화번호 뒤4자리 · NRC 참여여부 · NRC 이름)
checkins  (member_id, checkin_date, source) — (member_id, checkin_date) UNIQUE
```

주차는 **이벤트 시작일이 속한 주의 월요일**을 1주차 시작으로 자동 계산됩니다. 관리자가 시작일/종료일/주당 목표를 수정하면
모든 주차 구분과 성공 여부가 즉시 새 기준으로 재계산됩니다(과거 출석 기록은 그대로 유지).

## 6. 페이지 구조

**멤버 화면 (모바일 우선)**

| 경로 | 설명 |
|---|---|
| `/` | 이벤트 소개 + 본인 확인/최초 등록 |
| `/checkin` | 오늘의 코드 입력 → 출석 처리, 이번 주 스탬프판 |
| `/my` | 내 주간 출석 현황 + 지난 주차 기록 전체 |

**관리자 화면 (PC 우선, Supabase Auth 로그인 필요)**

| 경로 | 설명 |
|---|---|
| `/admin/login` | 관리자 로그인 |
| `/admin` | 대시보드 (참여자/오늘 체크인/WEEK SUCCESS/달성률 + 이번 주 성공자 리스트 + 오늘의 코드) |
| `/admin/today-code` | 오늘의 코드만 크게 보여주는 전체화면 (TV/데스크 모니터용) |
| `/admin/members` | 참여자 관리 — 필터/검색/월~토 출석표, 회원 클릭 시 정보 수정·수동 출석 추가/삭제·회원 삭제 |
| `/admin/settings` | 이벤트 시작일/종료일/주당 목표 설정, 주차별 통계, CSV 다운로드(전체 · 성공자만) |

## 7. 운영 원칙 반영 현황

- 스태프가 매 수업 명단을 체크하지 않음 → 멤버가 QR로 셀프 체크인
- 스태프가 도장을 직접 찍지 않음 → 시스템이 자동으로 스탬프 UI 표시
- 하루 중복 출석은 DB unique 제약으로 원천 차단 (같은 날 오전/오후반 모두 들어도 1회만 인정)
- 주 3회 이상 자동 판정, 관리자는 "이번 주 성공자" 리스트만 확인하면 됨
- 100~300명 규모에서도 관리자 화면 하나로 전체 파악 가능 (필터 + 검색 + CSV)
- 다른 CRM/회원관리 시스템과 연동 없음, 이 이벤트만을 위한 완전 독립 프로젝트

## 8. 추가로 제안한 기능 (운영 효율/UX)

- **자동 재확인 카드**: 한 번 본인 확인을 마치면 기기에 이름만 저장해두고, 다음 방문 시 "OOO님 맞으신가요?" 카드로 한 번의 탭만으로 출석 화면까지 이동 (매번 이름/전화번호를 다시 치지 않아도 됨 — 5초 체크인 목표 지원)
- **전체화면 오늘의 코드 페이지**(`/admin/today-code`): 스튜디오 TV에 그대로 띄워두기 좋은 대형 숫자 화면, 1분마다 자동 갱신
- **성공자만 담긴 CSV 다운로드** 버튼을 전체 CSV와 별도로 제공 (리워드 대상자 확정 작업용)
- **관리자 수동 출석에 출처 표시**(`본인 QR` vs `관리자 수동`)로 데이터 신뢰도 확보

## 9. 개인정보 처리

이름, 휴대폰 번호 뒤 4자리, NRC 닉네임만 수집합니다. 이벤트 운영 목적 외 사용하지 않으며,
모든 데이터베이스 접근은 서버(Service Role Key)에서만 이루어지고 브라우저는 Supabase에 직접 접근하지 않습니다.
이벤트 종료 후 Supabase 프로젝트를 삭제하면 데이터가 완전히 파기됩니다.
